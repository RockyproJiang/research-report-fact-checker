# 研报财务数据纠错（Research Report Fact-Checker）

把券商研究报告里披露的财务数字，逐条对回上市公司年报原文，自动产出**《疑似错误清单》**、**页码级证据链**与**可直接替换的修改文本**。

核心取向是**误报控制优先**：宁可把可疑项放进「待复核」，也不把预测值、单季度值、分部口径当成错误报出来。

---

## 一、这个项目解决什么问题

研报里的财务数据常出现这类问题：抄错年份、单位混用（亿元/万元）、口径串用（归母 vs 合并）、四舍五入失真、引用错年份的公告。人工一页页回查年报又慢又容易漏。

本项目把它拆成两条流水线，用 `03_指标结果.csv` 衔接：

1. **阶段一 · 基准库**（`financial_analysis/`）：年报 PDF → 三表提取 → 科目标准化 → 8 项比率计算与勾稽校验 → 落盘成可复用的「基准库」；
2. **阶段二 · 纠错**（项目根目录）：研报 PDF → 抽取财务声明（带页码/原文）→ 按 `(公司, 报告期)` 关联基准库 → 归一化比对（容差 0.5%）→ 输出疑似错误清单、修改建议与证据链。

## 三、功能特性

### 阶段二 · 研报纠错

- **两条核查线**
  - `main.py`：全口径核查——收入 / 利润 / 资产 / 现金流、估值倍数（PE / PB / PS / 目标价）、统计口径、单位敏感句、引用溯源；
  - `main_indicators.py`：8 项基准比率专项核查，对应《研报财务数据比对判定规则》主线。
- **声明抽取保留页码**：`pdfplumber` 逐页解析，正文走 `extract_text()`，财务摘要表走 `extract_tables()`，用 `2024A / 2025A / 2026E` 列头给每个数值绑定报告期；每条声明记录页码、行号、原文与数值单位。
- **范围判定（防误报第一道闸）**：预测、单季度、TTM、估算值、8 项清单之外的指标 → 只留痕、不比对，原因列必填。
- **归一化比对**：`40.22% ≡ 0.4022`、亿元/万元/元同量纲换算、同比 pp 双路径（研报直接给 pp，或由本期/上期两个毛利率相减推算）。
- **确定性舍入复核**：由研报两位小数披露精度就能解释的差异 → 判「误报剔除」，不计错。
- **口径差异单独留痕**：如研报写「归母净资产增长率」而基准是「资本积累率（权益合计口径）」，以及分部 / 业务线 / 产品线毛利率，判「口径差异」不计数。
- **LLM 复核 + 可执行建议**：只做结论复核与生成可直接替换原文的文本，禁止编造上下文之外的数字；**无 Key / 断网 / 额度耗尽时自动回退规则版建议，流水线不中断**。
- **四维质量自评**：来源定位率、建议可执行率、待复核占比、核查维度覆盖。

### 阶段一 · 基准库

- 自动识别合并资产负债表 / 利润表 / 现金流量表，保留 PDF 页码与表格位置；
- 关键信息提取：审计意见、归母净利润、扣非归母净利润、非经常性损益、现金分红、总股本、合并范围变化；
- 勾稽校验：资产负债表平衡、负债分项、营业利润、净利润、现金净增加、未分配利润、营收现金含量等；
- 异常规则引擎 + 行业特性豁免（半导体高流动比率、重资产成本现金支付差异等）；
- 结构化基准包（JSON + CSV），供阶段二与下游系统使用。

> 阶段一的完整说明见 [`financial_analysis/README.md`](financial_analysis/README.md)。

## 五、环境要求

- **Python ≥ 3.10**（代码使用 `X | None` 类型注解；开发与验证环境为 3.13）
- 依赖：`pandas`、`pdfplumber`、`openai`、`python-docx`
- 阶段一、阶段二共用同一套依赖

```bash
python -m pip install -r requirements.txt
```

可选：`python -m pip install python-dotenv`（用于自动加载项目根的 `.env`）。

> `pdfplumber` 读取的是 PDF 的**文本层**。扫描版（纯图片）年报需要先 OCR，否则提取结果为空。

## 六、配置 API Key（重要）

**密钥不写在代码里。** `config.py` 只从环境变量读取，仓库中不含任何 Key。

| 环境变量 | 是否必填 | 默认值 | 说明 |
|---|---|---|---|
| `DEEPSEEK_API_KEY` | LLM 功能必填 | 空 | 未设置时自动跳过 LLM，回退规则版输出 |
| `DEEPSEEK_BASE_URL` | 否 | `https://api.deepseek.com` | 兼容 OpenAI 协议的任意端点 |
| `DEEPSEEK_MODEL` | 否 | `deepseek-v4-flash` | 模型名 |
| `KEEP_OUTPUT` | 否 | — | 阶段一设为 `1` 时不清空 `financial_analysis/output/` |
| `EXTRACT_DEBUG` | 否 | — | 阶段一设为 `1` 时打印提取调试信息 |

PowerShell：

```powershell
$env:DEEPSEEK_API_KEY = "sk-..."
python main.py
```

bash / zsh：

```bash
export DEEPSEEK_API_KEY="sk-..."
python main.py
```

也可以把变量写进项目根的 `.env`（已在 `.gitignore` 中屏蔽，安装 `python-dotenv` 后自动加载），模板见 [`.env.example`](.env.example)。

> ⚠️ **不要把真实 Key 提交到仓库。** 一旦误提交，仅删除文件无效（历史里仍在）——必须到平台上**吊销并重新生成**，再清理 git 历史。

## 七、快速开始

### 1. 准备材料

```
financial_analysis/files/   ← 年报 PDF（第一信源），建议命名：<公司简称>：<年份>年年度报告.pdf
files/                      ← 研报 PDF，文件名必须含「研报」二字
```

> 出于体积与版权考虑，仓库**不包含任何 PDF**（`*.pdf` 已在 `.gitignore` 中屏蔽），需自行准备。两个 `files/` 目录已用 `.gitkeep` 占位，克隆后即可直接放入文件。

### 2. 阶段一：生成基准库

```powershell
cd financial_analysis
$env:KEEP_OUTPUT = "1"     # 关键：否则会清空 output/ 下已有的基准
python main.py
cd ..
```

验收要点（缺一不可）：

- `financial_analysis/output/<公司：报告期>/03_指标结果.csv` 存在，且含 8 项指标全部行；
- `02_标准化数据.csv` 非空；有科目未映射时运行 `python debug_map.py "<报告名>"`，按提示补 `mapping/subject_map.csv` 后重跑；
- `07-4_勾稽校验结果.csv` 全部通过；`07-5_汇总风险.csv` 无「源文件内部不一致」留痕。

### 3. 阶段二：核查研报

```powershell
# 全口径核查：自动扫描 files/ 下文件名含「研报」的 PDF
python main.py

# 8 项比率专项核查：默认标的由 DEFAULT_DRAFT_NAME 指定
python main_indicators.py

# 指定具体研报（文件名去掉 .pdf 后缀）
python main_indicators.py "兆易创新研报"
```

清空历史产物后重跑：

```powershell
python main.py --init        # 等价于 --clean / --clear
```

### 4. 查看结果

`output/<公司>/07_核查报告.md` 是汇总报告；`04_核查结果.csv` 是《疑似错误清单》本体。仓库内已带 5 家公司的示例产物（中芯国际 / 兆易创新 / 同仁堂 / 药明康德 / 贵州茅台），可直接打开对照。

## 九、判定规则与容差

### 判定取值

| 判定 | 含义 | 是否计入错误数 |
|---|---|---|
| `一致` | 差异在容差内 | 否 |
| `疑似错误` | 超出容差，判 `数值不一致` 或 `年份不一致` | 是 |
| `误报剔除` | 研报披露精度 / 舍入可解释 | 否 |
| `口径差异` | 归母 vs 合并、分部 vs 合并等口径不同 | 否 |
| `附加观察` | 8 项基准之外的衍生指标（速动比率、每股经营现金流等） | 否 |
| `无法核实` | 研报有声明但基准库无对应数据 | 否（列待复核） |

### 容差参数（`config.py`，单一来源）

| 参数 | 值 | 含义 |
|---|---|---|
| `NUM_TOL` | `0.005` | 比率类相对误差 ≤ 0.5% 判一致 |
| `NUM_SOFT` | `0.02` | 0.5% ~ 2% → 待复核，不直接判错 |
| `MULT_TOL` | `0.02` | 估值倍数重算容差（股价/股本取数日期差异） |
| `UNIT_TOL` | `0.005` | 单位换算识别容差 |
| `GOULI_TOL` | `0.01` | 草稿内部前后一致容差 |
| `PP_TOL` | `0.20` | 同比 pp 为差值量纲，改用绝对容差 |
| `SEVERE_MID` / `SEVERE_HIGH` | `0.10` / `0.50` | 差异率 → 中 / 高危分档 |

### 纳入比对的 8 项指标（白名单）

`流动比率`、`现金流量比率`、`资产负债率`、`产权比率`、`毛利率`、`毛利率同比pp`、`营业现金比率`、`资本积累率`

此外 `每股经营现金流`、`速动比率`、`净资产收益率` 作为**附加观察**：只提示口径需人工核对，不判数值错误。

## 十、容易踩的坑

1. **阶段一默认清空 `output/`** —— 跑之前务必 `KEEP_OUTPUT=1`，否则既有基准库会一起被删。
2. **研报文件名必须含「研报」** —— 阶段二按 `suffix in (.md/.txt/.docx/.pdf) and "研报" in stem` 扫描，命名不符会静默跳过。
3. **表格列错位会制造假错误** —— 财务摘要表若 `extract_tables()` 列错位，数值会绑错年份，直接产生「年份不一致」误报；换新标的时建议人工抽查一次绑定结果（用 `debug_draft.py`）。
4. **基准库目录名靠冒号切分** —— 形如 `中芯国际：2025年年度报告`，公司简称取冒号前段；全角/半角冒号都兼容，但不要改动这个命名约定。
5. **扫描版 PDF 无文本层** —— 提取结果为空，需要先 OCR。
6. **`main_indicators.py` 一次只处理一个标的** —— 由 `DEFAULT_DRAFT_NAME` 或命令行参数指定。

## 十二、数据与合规

- 仓库**不含**年报 / 研报 PDF：`files/` 与 `financial_analysis/files/` 下的 `*.pdf` 已在 `.gitignore` 中屏蔽。券商研报通常有版权限制，不建议再分发。
